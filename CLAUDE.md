# Stream Deck Dial Multi Volume Control

Elgato Stream Deck plugin (TypeScript, built with rollup, subfolder `volume-control-multi-dials`) that controls an app's Windows volume via a Stream Deck+ dial, using the native module `node-audio-volume-mixer` for per-process audio session control.

## Deploy loop — required after every change

After **any** change to plugin code, the manifest, or property inspector HTML, run the full loop below. Do this automatically, without being asked each time:

```powershell
$env:PATH = "C:\Program Files\nodejs;" + $env:PATH
cd "X:\-- WORK\-- GitHub\Stream-Deck-Dial-Multi-Volume-Control\volume-control-multi-dials"
npm run build
npx streamdeck restart com.morgan-scruggs.volume-control-multi-dials

Stop-Process -Name "StreamDeck" -Force -ErrorAction SilentlyContinue
Start-Sleep -Seconds 2
Start-Process "C:\Program Files\Elgato\StreamDeck\StreamDeck.exe"
```

**Always fully quit and relaunch `StreamDeck.exe` (the last three lines above), not just the plugin restart.** Some manifest-driven UI (e.g. the Encoder `triggerDescription` legend shown in the actions list) is only read by Stream Deck's own UI at its own startup, and is not refreshed by `streamdeck restart <uuid>` alone (that only restarts the plugin's backend Node process).

## Environment quirks

- **The project lives on a network drive** (`X:` mapped to `\\192.168.1.181\Data\...`). Node.js is installed via `winget install --id OpenJS.NodeJS.LTS` but is not on PATH for new shells — prepend `C:\Program Files\nodejs` to `$env:PATH` each session.
- **`npm install` needs `--ignore-scripts`.** `node-audio-volume-mixer` has `gypfile: true`, which makes npm try to compile it via node-gyp (no Python/C++ toolchain present). The package ships a prebuilt `build/Release/addon.node`, so `--ignore-scripts` skips the unneeded rebuild.
- **The native `.node` binary gets OS-locked while the plugin is running.** Rebuilding while Stream Deck has the plugin loaded fails with `EPERM` trying to replace `sdPlugin/bin/node_modules/node-audio-volume-mixer`. [rollup.config.mjs](volume-control-multi-dials/rollup.config.mjs)'s `copy-native-modules` step catches this and keeps the existing copy rather than failing the build — this is expected, not an error to chase.
- **The installed Stream Deck plugin folder is a symlink**, not a copy: `%APPDATA%\Elgato\StreamDeck\Plugins\com.morgan-scruggs.volume-control-multi-dials.sdPlugin` → the project's own `.sdPlugin` folder. So a build's output is instantly "installed" — no separate deploy/copy step needed.
- Plugin logs write to `<sdPlugin>/logs/com.morgan-scruggs.volume-control-multi-dials.<N>.log` (rotated numerically) — prefer `streamDeck.logger` calls for debugging; they show up there.

## Icons

Static plugin icons (volume action icon/key, plugin category icon, marketplace icon) use the same speaker+mixer glyph, generated by [scripts/make-combo-icon.ps1](volume-control-multi-dials/scripts/make-combo-icon.ps1). Re-run that script and redeploy after any icon changes rather than hand-editing PNGs.

Per-app icons (e.g. a game or browser's own icon, shown in the Application picker and on the dial) are extracted at runtime and cached under `%APPDATA%\com.morgan-scruggs.volume-control-multi-dials\icons\` — **deliberately outside the plugin's own `.sdPlugin` folder**, not `imgs/actions/volume/dynamic/` as in earlier versions. Marketplace-installed plugins ship from a DRM-protected package, so the installed plugin folder can't be assumed writable at runtime; keeping this cache external also stops this dev machine's cached icons from being bundled into the `.streamDeckPlugin` package when running `streamdeck pack`. See `DYNAMIC_ICON_DIR` in [volume-control.ts](volume-control-multi-dials/src/actions/volume-control.ts).
